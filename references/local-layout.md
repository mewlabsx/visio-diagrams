# 有约束的局部优化与两列折排

入口仍为 render-visio.ps1；JSON 提供 localLayout 时调用 local_layout.py，并重新生成全部线路，而非沿用旧端点。依赖 Python 标准库，无 Archify 依赖。当前上限 40 个节点、80 条线；输出 planned.json 和 validation.json 记录策略、移动与搜索状态数。

## 局部微调

```json
"localLayout": {
  "adjust": {"order":["b","c"],"maxShift":0.5,"step":0.5,"maxRounds":2,"minGap":0.15},
  "routing": {"maxStates":80000,"clearance":0.18,"bendPenalty":2,"crossingPenalty":4}
}
```

order 是显式的后续顺序，相邻项必须具有有向可达关系。尝试节点及 order 中全部后续节点沿 x 或 y 等量同向移动；固定节点、页边界和 minGap 不满足时拒绝该候选。每轮只接受总转折数严格减少的候选，最多五轮；累计每轴位移不超过 maxShift。接受一次移动后，为该轴上的受影响节点锁定方向，后续轮次不能反向移动。

未列入 order 的节点保持原位，其线路仍重新计算。连接关系和文字保持不变；该模式不自动推断完整流程顺序或调整节点大小。无改善保留初始可行布局；初始路线不可行或搜索超预算默认报错并保存失败诊断。failurePolicy=preserve 可尝试原布局排线；仅原布局通过检查时交付 DEGRADED，否则仍失败。详见 configuration.md。

## 长纵向流程折排

```json
"localLayout": {
  "fold": {
    "mode":"auto", "minNodes":8,
    "mainPath":["start","step1","step2","step3","step4","step5","step6","end"],
    "branchAnchors":{}, "firstCenter":4, "columnPitch":6, "rowGap":0.5
  },
  "routing":{"maxStates":150000}
}
```

auto 模式检测主路径近似单列（中心 x 偏差默认小于 0.5 英寸）且节点数不少于 minNodes。根据主路径节点数，在接近中点、切分两侧都不是判断节点的位置切分，左列从上到下读完，再读右列。保留完整跨列连接；分支由 branchAnchors 显式指定主路径锚点，保留原相对位移。主路径相邻节点必须有实际连线；缺失锚点、重叠、固定节点和容器会拒绝。页宽高根据结果调整，节点间隔使用 rowGap。

折排属于版式重排，不受局部 maxShift 限制；两者不能在同一请求中开启。折排不根据任意复杂判断块自动推断安全边界；主路径与分支锚点由制图者提供，之后必须检查阅读顺序。

## 路由与验收

采用节点边界、避让距离和端点构成的有限正交网格，带方向的最短路搜索比较长度、转折和交叉惩罚。按输入线序逐线保留已占用路径，禁止正长度共线重叠，禁止穿过节点及无关节点的避让区域。同一节点侧存在多条线时当前要求显式选择不同侧端口；不自动均分这一模式的共享端口。菱形仍连接顶点。

标签在候选线段周围有限试放，检查与节点、所有线路及已放标签的矩形碰撞。文本尺寸是保守估计，不能替代视觉检查。跨线可以存在，搜索只施加惩罚，不保证零交叉；也不保证全局最优。Visio 保存后逐点核对线路，移动节点后需重新运行规划，不具备交互自动重排。

当前不支持容器、预置独立文字节点、泳道、UML 特殊端口语义。适用于已给定节点几何及端口的小型流程/组件图。算法按输入线序作启发式选择，失败可调整端口或线序，不宣称任意复杂图均可生成。

实测：局部示例中 b、c 同向上移 0.5 英寸，转折从 2 降至 0；14 节点、15 线的发布流程折为两列，保留两个判断、两条回路，全部原生路径保存核对通过。
