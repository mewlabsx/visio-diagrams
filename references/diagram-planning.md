# 图型、重复结构、澄清与局部让步

本文件是 Agent 的规划与交互规则，不是新的布局算法。先据此理解需求，再将已确认的
内容转为当前后端支持的输入。不得把规划记录中的字段当成生成器已经支持的 JSON 参数。

## 1. 判断图型和规则来源

用户明确命名的图型优先于自动推断；用户后续明确修订优先于先前规则。
分别记录图型、记法、表达目的、真实包含关系和排版分组。用户口中的“一/二/三级”
可能是排版分类，不应因此改写实际 parent 树。

每项约束记录：来源（用户/图型记法/结构推断/默认偏好）、作用范围、是否可让步。
图型名称是默认策略的线索，不能仅凭“架构图”推断整张图必须分层或矩阵排列。
局部重复结构只影响该局部；只有用户明确要求或相应记法确有要求时才成为硬约束。
当明确要求相互矛盾时，不自行降级其中一项为偏好，向用户澄清。

| 图型 | 保留的语义/记法 | 默认布局与可调整部分 | 当前现成生成能力 |
|---|---|---|---|
| 基本流程图 | 步骤方向、条件分支、回路；判断接入合法顶点 | 主路径明确，分支侧置；宽度/间距/分列可调整 | 基础流程与有界路线已实现 |
| 分层/矩阵架构图 | 业务关联、真实归属；明确指定的层次/矩阵 | 同层对齐或同编号对齐；根据结构判断，非一律硬约束 | 基本图元/原生容器已实现，完整矩阵求解尚未实现 |
| 原理/机制示意图 | 因果、作用方向、关键链路、反馈 | 默认自由布局，不强制等大框、矩阵或固定方向 | 基本图元可表达；不是电路等专业记法的支持声明 |
| 网络架构图 | 已知设备/接口连接、区域归属、链路类型 | 优先重复单元组合；区域间可灵活组织 | 基本图元/有界排线可用，专门网络模板与组合求解尚未实现 |
| 部署拓扑图 | 实际部署位置和通信关系，不从功能架构猜部署 | 组间位置和间距可调整 | 已知输入可用基本图元/容器表达 |
| 组件接口图 | 接口方向、调用或数据含义 | 位置灵活，优先可读；不强制中心辐射 | 基本图元与有界路线可用 |
| UML 时序图 | 参与者/生命线、消息顺序和类型、条件/循环范围 | 参与者横向顺序、事件间距、标签可调整 | 专用生成与验收尚未实现 |
| 泳道图 | 职责主体、活动归属、交接、使用阶段时的阶段归属 | 横/纵泳道、顺序和宽度可调整 | 原生泳道生成与验收尚未实现 |

时序图不能套用架构图的端口等分：消息位置应符合事件顺序；默认垂直距离不表示真实耗时。
泳道不能为了缩短线路而改变活动职责归属。通常将“泳道图”解释为跨职能流程图；
明确要求 UML 活动图或 BPMN 时使用相应记法，不混用。专业原理图（如电路图）还要遵守
其连接和符号语义，不能仅因“原理图”三个字就视作任意自由图。
检查对应模板/模具及后端能力；Visio 有模板不代表本 skill 已经支持。
尚未实现的图型应说明当前能力，再整理需求或明确替代方案，不静默画成普通流程图。

## 2. 识别重复结构和表达尺度

数量大不等于结构重复。比较角色组成、内部关系、可参数化差异与对外接口职责，
而不是只比较名称或外观。模板代表一类结构，实例代表具体单位；同类实例可以有不同外部连接对象。

| 输入 | 决策 |
|---|---|
| “20 个单位，每个包含 A/B/C，内部关系相同” | 模板候选明确；按内部是否需展开选择表达尺度 |
| “20 个单位分三类，各类结构如下” | 三类模板与各实例连接图 |
| “20 个单位组成与接入均不同” | 独立实例，不强行复用 |
| 只有“绘制 20 个单位的架构图” | 澄清组成是否统一及内部是否展开 |

信息充分且需要展开重复单元时，先制作每类结构模板（内部节点/路线、真实尺寸、
外部接口和通道空间），再以实际尺寸制作实例连接图，最后整体填入并连接对应接口。
缺少尺寸/接口时不能先用任意占位框做定稿。展开冲突时调整受影响的局部，而非持续缩字号。
当前可由 Agent 编排已确认的模板实例，但脚本尚无通用模板实例化、全局组合布局和自动分类器。
只需要总览时保持实例级连接，不无意义展开内部。

关系精度区分：明确成员连接、集合关联、已知链路束、未确定关系。
“A 组连 B 组”不能展开成全连接；链路聚合要标注含义，未知连接保留待确认。
布局可以决定怎样画，不能补造实际连接、职责或部署事实。模糊关系不能仅靠一种线型表达，需文字说明。

## 3. Agent 需求澄清

在已提供信息与本次上下文中先寻找答案，不重复询问。只询问会改变图意、图型、
实际成员/连接或关键排版承诺的问题；一般配色、间距等可采用明确默认值。
尽量合并关联问题，并解释答案影响的选择；避免要求用户逐个描述大量相似单位。

例：“这些单位的内部结构是统一的、分为几类，还是各不相同？图中需要展开内部，
还是只展示单位之间的关系？”

宿主有适合的用户提问工具时使用可选项/自由文本；没有时直接通过对话提问。
不依赖固定工具名称、特定模式或 UI。需求澄清与操作权限审批分开，遵守宿主对工具用途的限制。
提问不代表用户回答；未响应不等于同意默认选项。关键答案待确认时不做依赖该答案的定稿，
可以继续组织无关内容。对可选外观问题可说明默认值并继续。
无人交互场景保留未知字段或交付明确的未定稿总览，不宣称关键关系已确认。
仅在不会改变图意且已获范围授权时，未知局部可以标记“待确认”继续表达。

## 4. 冲突优先级和局部让步

1. 保留业务关系/方向、真实成员、所选记法、用户明确锁定的要求，以及不穿节点、不共线重叠和可读空间。
2. 保留明确要求的矩阵对齐、等大容器、指定横排/纵排等排版承诺。
3. 在允许范围内优化交叉、转折、端口等分、通道和节点移动；推断/默认规则可局部让步。

显式锁定的位置或端口属于第一类；算法不得为了满足第二/三类自行解锁。
两项不可让步要求冲突时先澄清；软约束冲突时选择最小影响调整，记录原因、范围与前后差异。
不静默把局部修复扩大为全图重排，不改变图意来满足几何检查。
用户后续明确选择替代方案时更新记录，避免反复恢复已被用户否定的布局。

单线矩形连接默认两框中心对齐、端点居中；不是所有图型的普遍硬要求。
共享边若选“全边内点等分”，n 个端口位于 i/(n+1)，而非靠近角部的留白区间两端。
直连必须满足绝对坐标相等；两端取相同分数并不保证宽度不同的框能够直连。

矩形分派的规划候选：可自由移动时让目标中心对齐分派点；要求一致排列且方向可变时
比较纵排/横排；必须横排时可上下交替接入并预留分开的通道。不能为严格等分破坏明确排版。
同一横排组的外部连线可交替接顶/底中点；最高绕行线与源框顶边之间保留可见间距。
右侧到右侧连接可优先比较两折 U 形绕行，但有障碍时允许局部调整，不能强制所有情况都两折。
这些是 Agent 规划规则；当前脚本的 spreadPorts 仍是留白区间均分，未实现上述联合求解。

## 5. 矩阵与容量

N 个域、各域 m_i 个元素：以 max(m_i) 建立共同槽位，相同编号居中对齐；
用户要求等大外框时，较少元素的域保留空槽位。外部行连接组占用网关上的一个区间，
各组中心等距，区间以最长组为标准；较短组的端点在同长区间内均分，单端点居中。
先明确是否保留空槽位、编号有无缺口，以及域内链路和行连接组如何共同使用端口。

目前容器按真实成员收紧，没有统一矩阵槽位/共享外框尺寸模型；不能声称只传参数就会生成等大域。
先按字号、文字、端口数、通道数量计算空间容量；放不下时扩页、重排或拆图。
字号按输入保留，不把持续缩字/挤线作为冲突修复方法；最终按实际观看尺寸检查。

## 6. 规划记录、修订和验收

记录足以解释重要决策的内容即可：图型/记法、重复模板与实例、确认/未知的关系、
重要约束的来源与范围、用户回答/锁定、选用布局、让步及受影响区域。
复杂或需多轮修改时可保存独立 .planning.json；它不是 render_native.py 自动消费的输入。

修改节点/结构后先复核相关边、父容器、邻近通道和同一布局组；不足时再说明扩大范围的原因。
当前生成器通常重新规划整图，尚无局部增量排线；不要把上述工作原则当成已实现的局部算法。
修改现有 VSDX 先复制，当前入口不能无损导入/修改原图。

验收分三层：语义与图型规则；空间/布局与让步；原生对象、真实渲染及被测编辑行为。
离线检查、原生验收与视觉审查分别报告，未做项写 NOT_RUN；规则文档存在不证明实际 Agent 会正确决策。
